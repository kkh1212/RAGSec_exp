# v1 → v2 탐색

| 동작 | v1 보존 설정 | v2 기본 |
| --- | --- | --- |
| 문서 후보 | 단일 문서 제목·본문 마스킹 | 독립적인 MASK_DOCUMENT / DROP_DOCUMENT |
| 삭제 | 빈 문자열 변환 최종 대조 | 실제 슬롯 제거도 후보 발견에 사용 |
| 부분 탐색 | 성공한 전체 마스킹 후보의 복원 | 전체 성공과 독립적인 전 문서 직접 구간 탐색 + 복원 |
| 문서 조합 | 1개 | 고정 순서의 2개 조합 |
| 최종 검증 실패 | 기존 후보 fallback | 부분/조합/다른 후보 탐색 재개 |
| 기본 요청 예산 | 20 | 48 |
| 최종 생성 예약 | 2 + 선택 삭제 대조 1 | 4 |

## 고정 일정

문서 순서는 검색 결과 튜플의 실제 순서다. rank/score/공격어/LLM 위험도/정답으로 정렬하지 않는다. 전체 단계는 문서별 마스킹 후 삭제를 시험한다. 발견 후보는 변경 문자 수, 원래 문서 순서로 정렬한다.

부분 단계는 제목과 본문을 별도 원문 좌표로 유지한다. 문장부호/개행 경계를 쓰고, 길거나 구두점 없는 문자열은 고정 문자 블록으로 분할한다. 필드의 큰 연속 범위부터 너비 우선으로 하위 범위를 예약하며 문서 간 round-robin으로 기회를 나눈다. 부모 범위의 실패가 자식 시험을 막지 않는다. 일정에 없는 임의의 모든 부분집합까지 탐색하는 알고리즘은 아니다.

두 문서 단계는 원문 인덱스 조합 순서다. top-5면 10쌍, MASK/DROP 각각 최대 20개의 조합 입력이 있다. 동일 조합을 누적 변경하지 않는다. 매 시험은 불변 원본 문서에서 패치를 적용한다. 최대 동시 변경은 2개이며, 세 문서 이상과 두 문서의 임의 부분 구간 곱집합은 지원하지 않는다.

## 축소·검증

후보에 원본 request fingerprint, 생성 설정 fingerprint, doc ID, operation, 원문 좌표, 변경량, 응답 상태를 기록한다. 원문 복원 시 ANSWER만 채택하고 REFUSAL/OTHER/UNCERTAIN/실행 오류는 채택하지 않는다. 단계 예산은 후보 전체가 공유한다. 두 문서 후보에서는 불필요한 문서를 먼저 복원한다.

DROP_DOCUMENT를 슬롯이 남은 DROP_SPAN으로 바꿀 때에는 변경된 실제 입력을 먼저 호출해 ANSWER를 확인한다. 성공을 추정하거나 다른 입력의 관측을 재사용하지 않는다. 변환 실패 시 원래 삭제 후보를 유지한다. 원래 성공 operation은 full_patches/candidate_details에 남고, 적용된 표현은 best_patches/patches에 남는다.

전체 단계 후보 하나를 먼저 검증한다. 실패하면 남은 검증 횟수를 부분/조합 경로에 쓸 기회를 준다. 같은 실제 입력은 탐색 캐시/방문 집합으로 중복 호출하지 않는다. 같은 응답과 같은 남은 근거로 이미 탈락한 검증 입력도 반복하지 않는다. 이는 다른 작은 범위 실패를 추론하는 규칙이 아니다.

최종 baseline REFUSAL·patch ANSWER 호출은 fresh이며 캐시에서 대체하지 않는다. 최대 2번의 grounding 검사만 허용한다. 검증한 응답 그대로 반환하며 그 뒤 새 생성 호출은 없다. 다른 변환은 보조 관측이다. 삭제만 성공해도 최종 승인이 가능하다. 서로 다른 의미 상태가 확인되면 transformation_sensitive=true, 비교하지 못했거나 불확실하면 null이다.

`max_refinement_probes`에는 DROP 표현 변환 시험도 포함한다. 보조 변환 비교는 요청 전체 예산에 포함되며, discovery의 partial/pair 상한과 별도로 trace에 transformation_probe로 기록한다. 전 과정에서 요청 전체 48회가 우선한다. 호출 오류와 engine 수준 재시도도 각각 차감한다. adapter 내부 retry는 금지한다.

## 탐색 범위 보고

`unexplored`에는 단계, 일정상 후보 수, 시험된 수, 남은 수, doc/field/operation/원문 범위가 남는다. 비활성화한 단계도 표시한다. 예산 때문에 축소/검증을 완료하지 못한 사실도 기록한다. 성공해 조기 종료해도 미탐색 범위가 있으면 search_complete=false다.

search_complete=true는 **코드가 정의한 해당 유한 일정**을 끝냈다는 뜻이다. 모든 공격 구간이 없다는 결론이나 전역 최소 패치의 증명은 아니다. 각 요청 결과의 config/usage를 함께 비교해야 한다. 실제 공격 성공률을 측정한 자료는 아직 없다.

문서 수가 클 때에는 모든 조합 패치 객체를 미리 할당하지 않는다. 앞쪽 일정은 제한해서 만들고, 이후 미탐색 조합은 고정 문서 순서·operation 순서와 끝 제외 인덱스 범위/개수로 기록한다. 예산이 0이라 원본 재시도도 못 한 경우에도 문서/부분/조합의 미탐색 범위가 남는다.
